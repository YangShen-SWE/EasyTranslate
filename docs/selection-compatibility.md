# 选区边界与应用兼容待验矩阵

记录日期：2026-10-16；对应源码 v2.1.6（D06）。这是待验清单，不是全系统支持声明，也不是已发布安装包说明。

## 已实现的边界

- 单次完整选区上限为 **1000 个 UTF-16 代码单元**，包含首尾空白，在去除空白之前计数。普通中英文字符通常占 1 个单位，部分字符（如 😀）占 2 个单位；不是 1000 个单词、可见字符或字节。
- Windows UI Automation（UIA，Windows 界面自动化）最多探测 1001 个单位，用多出的一个单位判断是否超限，不再直接把 `GetText(1000)` 的前缀当作完整选区。超限返回不含原文的 TooLong，界面提示缩短，保留译文标“上次结果”，不对本次超长选区读取密钥或发起翻译。不会先截断再上传，也不改成无限量抓取。
- 确认空选区/允许长度内纯空白为 None；目标不支持、协议损坏或无法判断时为 Unknown，两者不应混为一类。超过探测上限的空白同样保守报 TooLong，因为未读取的后续部分可能有文字。
- Java 解码端再次检查原始长度；不合法的 Base64/UTF-8 不替换成看似成功的文本。Found 的直接构造也不能塞入超过上限的文本。
- 不支持不连续多段选区：UIA 返回多个范围时拒绝，仅报无法读取，不悄悄上传第一段。只提供图像的 PDF、受保护区域和不提供 TextPattern 的控件仍可能读不到；不新增 OCR 或剪贴板模拟复制。

对应实现：[Windows选区服务](../EasyTranslate/src/main/java/com/easytranslate/service/selection/WindowsSelectedTextService.java)、[结果契约](../EasyTranslate/src/main/java/com/easytranslate/service/selection/SelectionResult.java)、[翻译用例](../EasyTranslate/src/main/java/com/easytranslate/usecase/TranslateSelectionUseCase.java)。

## 捕获与焦点的真实限制

1. Tab 的原生通知经后台执行器，之后才启动 PowerShell/UIA 捕获；最新意图编号不是按键瞬间的选区快照。启动延迟和窗口切换可能让捕获落在另一时刻。
2. 脚本开始时记录前台窗口，候选优先为焦点控件，其次为鼠标所在控件；候选必须属于同一前台窗口。D06给向上遍历的每个父控件加相同归属检查，避免爬出该窗口后继续找选区。
3. D06在输出前再次读取前台句柄，检测到前台改变则返回 Unknown。它只检测两次采样的差异，不覆盖 A→B→A、窗口内焦点变化、采样后再切换，也不能恢复原始按键时的窗口。较晚开始的捕获可能一开始就记录到 B。
4. 鼠标候选可能不是用户想翻译的控件；提供者可能返回陈旧、部分或错误选区。多段/嵌套/浏览器PDF提供者是否准确必须逐应用实测。后台捕获不得用“单元测试通过”冒充已消除焦点风险。
5. 全局 Tab 对原软件导航、长按、组合键、输入法候选态的影响留到 D07；自动显示/键盘进入/不抢源焦点留到 D08。本次没有吞键、接管输入法或用剪贴板回退。

## 最小手动验收流程（尚未执行）

1. 指定一个目标应用和版本，记录Windows版本/显示缩放/源码版本；关闭其他捕获探针。只准备自造文本，不读取/打印私人选区，不把密钥、日志或私人原文写入仓库。
2. 分别准备 `a` 重复999次、1000次、1001次，以及空选区、空格/换行、`😀`重复500次和末尾再加`x`的样例。验证999/1000末尾未丢失、1001与1001单位的补充字符样例报超长；前1000个为空格但后面有字的样例也不能被当作普通空选区。
3. 先隔离验证捕获，不调用翻译API。现有 SelectionDebug 会在5秒后读取当前选区并打印文字，只能在操作者明确切到自造样例时手动使用；它是诊断入口，不代表生产在线开关已同意，不得直接拿当前桌面或个人选区试跑。本次没有运行该入口。
4. 然后分别验证焦点/鼠标同控件、不同控件、触发后立即切窗、同窗口换焦点、多段选区。记录原文是否与样例一致、是否安全报Unknown；不以“未崩溃”代替捕获准确。
5. 如另行进行真实翻译链验证，操作者需阅读联网说明、明确同意并在本机配置自己的有效密钥；费用与数据上传由本机操作者确认，不在聊天中提供密钥。确认超长样例没有本次翻译调用，旧译文明确保留；换短选区重新触发才成功。已存在的其他在途请求仍可能完成/计费，不把它们误认为本次超长请求发送。
