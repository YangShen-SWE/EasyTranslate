# EasyTranslate Development Notes — Version 1

I am keeping this as a record of how the first version came together, rather than a list of current features. Version 2 has DeepSeek connected, a redesigned UI, settings, and animations. The latest progress is in the [Version 2 notes](开发笔记（第二版）.md) and [README](../README.md).

It started when I saw an input method with built-in translation. I thought it was interesting and wanted another reason to work on my English. Once I started writing it, though, having ideas and getting them to work turned out to be very different things. Just reading selected text took quite a while.

So I made the goal smaller: select English text in another app, press tab, and display the original and translation in a little desktop window. Vocabulary, review, and input methods could wait. I left Rime alone and used selection translation as something to practice with.

## Where the early version got to

The earliest version could open an always-on-top, borderless JavaFX window. I could drag it, save its position on close, and restore that position next time. Pressing tab tried to read the current selection and display the original with a “mock translation.”

That mock translation really was just a few words added before the original. There was no online service or database yet. I wanted to make sure the whole path from selection to display worked before trying GPT or DeepSeek for real translation.

At the time, selecting and deselecting text in Chrome could be distinguished. Some desktop apps only exposed the selection when the mouse was over it, and IDE editors were still unreliable. Some apps worked, but it was a long way from working everywhere.

## What I used

The main program uses Java, the interface uses JavaFX and FXML, and Maven manages the dependencies. The compilation target at the time was JDK 25, with JavaFX 21.0.6. Global Tab observation uses JNA to call a Windows low-level keyboard hook. Selection reading uses Windows UI Automation through a PowerShell script launched by Java. Window coordinates go into Preferences.

I split things up following MVVM, mostly to stop everything from ending up in the application class:

- `view` and `FloatingViewController` handle the interface, dragging, and closing.
- `FloatingViewModel` holds the original and translation, using JavaFX properties to update the display.
- `Translation` represents one original text and its translation.
- `service` handles Tab, selection, and translation separately. At that stage it used `MockTranslationService`.
- `TranslateSelectionUseCase` connects selection reading to translation, returning an empty result if there is no valid selection.
- `EasyTranslateApplication` puts the objects together and hands results back to the JavaFX UI thread.

Selection results are split into `Found`, `None`, and `Unknown`: text was found, there is no selection, or the program cannot reliably tell. At least that avoids treating “cannot read it” as “nothing is selected,” or grabbing old clipboard contents and calling them the latest selection.

## Things that were trickier than expected

I chose to observe Tab without blocking it. Selection reading runs in the background instead of doing slow work inside the keyboard callback. Repeated key presses and Alt+Tab were handled separately, but the original app still receives Tab, so conflicts with input methods and app shortcuts did not disappear.

I also considered simulated copying as a fallback. But what about what was already on the clipboard? Could it break images, rich text, or clipboard history? I wrote down the problem instead of adding it straight away.

Asynchronous translation has another catch: the first request does not necessarily finish first, so an old result can overwrite a new one. That stayed on the [issue list](待解决问题清单.md). Not seeing it in a single demo does not mean it is solved.

## What I was planning next

First replace the mock translation and get one real selection-to-translation flow working, then improve compatibility and request ordering. After that, I wanted to connect to local MySQL through JDBC, save successfully looked-up words, and gradually add counts, a vocabulary book, and review.

I was still interested in input methods, but left that for later. I had seen a few similar open-source projects and wanted to study their approaches. Reusing anything would also mean checking its license first.

Looking back now, online translation and the UI have moved forward, while word storage and input methods are still waiting. The full plan is in the [requirements](requirements.md). This page keeps the record of figuring out the first version.

A few days ago I saw an input method with built-in translation and thought it was amazing. It actually got me interested in learning ~~Danish~~ English again. # EasyTranslate 开发笔记（第一版）

这篇留着记录第一版当时怎么做的，不是现在的功能清单。到第二版已经接上 DeepSeek，也换了界面、加了设置和动效，最新进度看 [第二版笔记](开发笔记（第二版）.md) 和 [README](../README.md)。

最开始是看到一个带翻译的输入法，觉得很有意思，又想给自己找点学英语的动力。不过真开始写才发现，想法很多，实现起来完全是另一回事，光是读取选中文字就折腾了好久。

所以先把目标缩小：在别的软件里选中英文，按 tab，让桌面上的小窗口显示原文和译文。后面再想词本、复习和输入法，暂时不碰 Rime，先拿划词翻译练手。

## 当时先做到了哪一步

第一版最早能启动一个置顶的 JavaFX 无边框窗口，可以拖动，关闭时记住位置，下次恢复。按 tab 时尝试读取当前选区，读到文字就显示原文和“模拟译文”。

这里的模拟译文真的只是给原文前面加几个字，当时还没接在线服务，也没有数据库。先确认选中文字到窗口显示这一整条路能通，再考虑用 GPT 或 DeepSeek 做真正的翻译。

Chrome 的选中和取消选中当时能够区分；有些桌面软件要把鼠标停在选中文字上才读得到，IDE 编辑器还是不可靠。所以只能说有些程序能用，离到处都能用还差得远。

## 用到的东西

主程序用 Java，界面用 JavaFX 和 FXML，Maven 管依赖。当时编译目标是 JDK 25，JavaFX 依赖是 21.0.6。全局 Tab 观察通过 JNA 调 Windows 低级键盘钩子，选区读取走 Windows UI Automation，由 Java 启动 PowerShell 脚本完成。窗口坐标放在 Preferences 里。

代码按 MVVM 的思路分了一下，免得后面所有东西都挤在启动类里：

- `view` 和 `FloatingViewController` 放界面、拖动和关闭这些操作。
- `FloatingViewModel` 保存原文和译文，通过 JavaFX Property 更新显示。
- `Translation` 表示一条原文与译文。
- `service` 分别处理 Tab、选区和翻译，当时用的是 `MockTranslationService`。
- `TranslateSelectionUseCase` 串起读取和翻译，没有有效选区就返回空结果。
- `EasyTranslateApplication` 组装这些对象，把结果交回 JavaFX 界面线程显示。

读取结果分成 `Found`、`None` 和 `Unknown`。一个是读到了，一个是知道没有选区，还有一个是根本判断不了。这样至少不会把“读不到”直接当成“没选中”，也不会随手拿旧剪贴板冒充刚选的文字。

## 比想象中麻烦的地方

Tab 当时选的是只观察、不拦截，读取选区交给后台线程，不在键盘回调里做慢操作。长按重复和 Alt+Tab 做了区分，但原软件仍然收到 Tab，所以输入法和原软件快捷键的冲突并没有因此消失。

还想过拿模拟复制当后备，可是剪贴板里原来有东西怎么办，图片、富文本和历史记录会不会被改坏？先把问题记下来，当时没直接加。

异步翻译也有个坑：先查的词不一定先返回，旧请求可能把新结果盖掉。这项后来继续留在 [问题清单](待解决问题清单.md)，不能因为单次演示没遇到就算解决了。

## 当时准备往哪走

先换掉模拟翻译，跑通一次真正的划词翻译，再补兼容性和请求顺序。之后想用 JDBC 接本机 MySQL，存成功查过的词，慢慢做次数、词本和复习。

输入法仍然很感兴趣，但先放后面。看过一些类似的开源项目，之后可以研究做法，真要复用也得先看许可证。

现在回头看，接在线翻译和美化窗口已经往前走了一步，存词和输入法还没跟上。完整想法继续记在 [需求文档](requirements.md)，这篇就保留第一版摸索的过程。
