# 词本保存边界（D13）

## 当前状态

本次只落地可测试的事件/保存契约，不是完整词本。没有数据库、文件/Preferences存储、自动收集或UI保存按钮接线；现有单词本窗口仍是占位。MySQL/JDBC是否硬性要求未确认，因此没有迁移、安装驱动或增加服务。未完成的原生选区/IME/多屏和干净Windows验收仍保留，不拿本契约替代P0实机验收。

## 候选与保存

`VocabularySaveBoundary`由未来适配器显式注入`LatestTranslationCoordinator`的新重载；既有生产构造保持null，完全不启用收集。协调器在最新响应真正调用展示回调和成功状态回调后，再次核对intent及在线permit，才授予不可变Candidate。不是收到HTTP响应就保存；展示回调异常/重入触发/关闭不能授予资格。展示是回调已接受模型的契约，不是屏幕像素已绘制证明。

每次新触发立即撤销资格，即使旧译文仍可见；空选区、Unknown、过长、服务失败和关闭不复用旧候选。设置决定调用既有refreshOnlineAccess同样撤销。异步排队旧响应不能覆盖候选。Candidate.intent仅当前协调器会话有效，不可当数据库主键；保存动作必须携带实际展示快照的intent，旧快照返回STALE。

保守限定英文词/短语：1–5个词、源文归一化后最多80个UTF-16单位，ASCII字母及词内连字符/直或弯单引号；压缩空白、去首尾空白；释义非空、最多4000单位且无非法控制字符（允许换行/Tab）。规范key使用Locale.ROOT小写与统一单引号。句子标点、数字、其他语言暂不收录，不宣称语言识别或所有英文合法词形。该长度是词本策略，不改变划词1000字符上限。

仅显式`save(intent)`调用存储。Result区分SAVED、DUPLICATE、INELIGIBLE、STALE、STORAGE_FAILED；不能把任意返回当保存成功。进程仅记最后成功key以避免连点；跨条目/重启/多实例唯一性必须由Repository.insertIfAbsent按key原子保证。只返回INSERTED/ALREADY_EXISTS，不覆盖既有释义；无内存全量原文历史/无限增长去重集合。大小写和弯引号折叠可能合并同形异义词，是当前有意限制，未来支持多语言/词义时需要扩充唯一键并明确迁移。

## 失败与后续接线条件

Repository可以抛异常：边界只返回STORAGE_FAILED，不打印或透传可能含连接串、密钥、原文的异常；不污染翻译成功状态、不阻止下一次翻译、不自动重试。保留当前资格供用户明确重试。数据库已提交但客户端报错时必须靠原子唯一键实现幂等，而不是声称exactly-once。测试用假服务与内存仓库，不能证明真实数据库事务/持久化。

当前保存串行、同步持锁调用仓库，是尚未接入UI的边界；阻塞存储会阻塞调用线程。未来UI必须在FX线程外调度并定义保存与新触发/关闭的线性顺序、超时、线程安全和已发出保存的处理，不可以把这段同步调用直接放按钮/FX回调。本次不承诺取消已提交数据库操作，不吞Error等虚拟机故障。Boundary必须专属单一协调器会话，关闭后不可复用。

上线前还需确认：MySQL/JDBC是否课程硬约束、仅手动保存还是默认收集、存储位置/加密/删除/导出、语言和词义唯一键、真实事务与失败恢复、用户可见保存反馈/列表与后台执行、真实GUI/原生P0验收。不能在未确认时增加持久原文存储。测试与实际版本见[测试指南](core-tests.md)与[v2.1.13](releases/v2.1.13.md)。
