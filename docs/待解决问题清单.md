# Things I Still Need to Fix

The window looks better now, but looking good and working well are different things. I am keeping unfinished work here so I do not spend all my time adding cat animations. Updated for Version 2, 2026-09-28.

## An old translation can overwrite a new one

Every tab press currently starts selection reading and translation asynchronously. Requests do not necessarily finish in the order they were sent. If I look up A and then B, but A finishes last, it can replace B. A pending request can also show up after I clear the selection.

The plan is to number requests and let only the latest one update the UI. I can decide later whether older requests should be cancelled. Testing needs rapid selections of different words, plus clearing the selection and pressing tab again without an old result popping up. This code has not been fixed yet.

## Translation failures are not explained properly

The service throws errors for network failures, timeouts, and API errors. The window now shows a general failure message and points users to settings when the API key is missing. More specific messages for individual failure causes still need work.

I want a short failure message that keeps the last result while making it clear the new request failed. Offline mode, timeouts, missing or invalid keys, and empty responses all need testing. Otherwise it is easy to mistake an old translation for a successful new one. The online translation switch and explanation of what gets sent also need work.

## Some apps still do not expose their selection

Chrome and some desktop apps were tested manually before; IDE editors remain unreliable. The implementation uses Windows UI Automation and also tries the element under the mouse. That is not the same as recognizing arbitrary text on the screen.

I need separate results for browsers, text-based PDFs, Notepad, and IDEs. Simulated copying is a possible fallback, but clipboard restoration, multiple formats, and history need sorting out first. It has not been added. OCR for scans and images is outside this version too.

There is another limit: selection reading currently uses `GetText(1000)`, so longer text can be cut off. A scrolling UI does not mean the input layer can already read a whole long passage. Both ends need attention.

## How tab should coexist with apps and input methods

Tab is currently observed rather than swallowed, so the original app also receives it. Key repeat and Alt+Tab have been handled separately, but that does not solve conflicts during input-method composition.

Giving candidates priority, submitting Chinese with Tab, and submitting English with Tab+Space are future plans. None of that is connected yet. It needs testing in real apps; the animation listener is not an input-method feature.

## Let users choose the translation shortcut

The translation trigger is currently fixed to Tab. Add a shortcut setting that lets users choose and save a key combination, shows conflicts with common application and system shortcuts, and restores the choice after restart. Verify in browsers, text-based PDF readers, Notepad, IDEs, and input-method candidate mode. If there is no valid selection, the original application's key behavior must remain intact.

## Light and dark themes

The current window uses a dark background. Add a light theme with a white background and keep the dark theme with a black or near-black background. The setting should apply to the floating window and settings window, save across restarts, and keep text, controls, icons, and the cat decorations readable in both themes.

## Translate images and PDFs by dropping files onto the window

After downloading an image or PDF, let me drag the local file onto the floating window to translate its contents. Text-based PDFs need text extraction; images and scanned PDFs need OCR before translation. Show a clear result or an error when the file cannot be read, and do not add its contents to the vocabulary book automatically. File drag-and-drop and OCR are not implemented yet.

## The vocabulary book is still just an entry point

The button and separate window exist, but the page still says “Coming soon.” Local MySQL, JDBC, the schema, and the application's storage flow need to be connected before there is an actual vocabulary book.

Start by saving a valid word or phrase after its translation is successfully displayed, then add search, counts, and history. Failures, duplicate callbacks, ordinary typing, and paw taps must not count as lookups. Review playback, weighting, and archiving come later.

## There are still window and animation scenarios to test

The standalone UI check passed 44 checks in this round, covering things such as saved settings, hiding the original, animation reset, and listener startup. The native input probe saw left-side keyboard and mouse activity, and the text field received input normally. Right-side mapping was checked in code, but still needs a complete manual input check.

Multiple monitors, different scaling, fullscreen and elevated apps, and focus behavior during window switches still need testing. There is no reliable new screenshot of the animation version yet, so the old static screenshots cannot count as animation verification.

“Animations” can be disabled in settings, and hiding decorations stops the listener too. Long typing sessions, repeated toggling, and exiting need more observation. A clear message when listener startup fails would also help.

The intended behavior is in the [requirements](requirements.md). This is a to-do list; putting an item here does not mean it is fixed.

# 待解决问题清单

界面现在比之前像样了，但是好看和好用还是两回事。这里把还没处理完的东西记一下，省得后面只顾着给猫加动作。更新到第二版，2026-09-28。

## 连续翻译，旧结果可能把新结果盖掉

现在每次按 tab 都会异步读取选区、请求翻译，先发出去的不一定先回来。比如先查 A 再查 B，A 最后才回来，就可能把 B 的结果盖掉。取消选区之后，之前的请求也可能迟到。

准备给请求编号，只让最新一次请求更新界面；要不要取消旧请求后面再看。检查时要连续选不同的词，也要试一下取消选区后再按 tab，不能又冒出旧译文。这件事还没改代码。

## 翻译失败还没有好好告诉我

服务里会抛出网络失败、超时和接口错误。窗口现在会显示通用失败提示；缺少 API Key 时，也会提示去设置里保存。不同失败原因还需要更明确的提示。

后面想加简短的失败提示，保留上次结果但说明这次没成功。断网、超时、密钥缺失或无效、接口返回空内容都要试，不要让人对着旧译文以为刚刚翻译好了。在线翻译开关和发送内容说明也还要补。

## 有些软件还是读不到选区

Chrome 和部分桌面软件之前手动试过，IDE 编辑器仍不可靠。现在用 Windows UI Automation，也会尝试鼠标所在位置的控件；这不等于识别屏幕上的任意文字。

后面要分别记下浏览器、文字型 PDF、记事本和 IDE 的结果。模拟复制可以作为备选方向，但得先想清楚怎么恢复剪贴板、多格式内容和历史记录，暂时没有加上。扫描件和图片 OCR 也不在这版范围里。

还有个限制：目前选区读取用了 `GetText(1000)`，较长的文本可能截断。界面能滚动显示长文，不代表输入端已经能完整读取长段落，后面要一起处理。

## tab 和原软件、输入法怎么相处

现在只观察 tab，不吞掉按键，原软件也会收到它。长按和 Alt+Tab 做过区分，但这还不等于候选输入阶段的冲突解决了。

输入法候选优先、Tab 提交中文、Tab＋空格提交英文这些是后续想法，目前没有接入。要在实际程序里验证，不能直接把动效监听当作输入法功能。

## 在设置里自定义划词翻译快捷键

目前划词翻译固定由 Tab 触发。后续在设置里提供快捷键组合的选择、保存和重启恢复，并提示与系统或常见软件快捷键的冲突。需在浏览器、文字型 PDF 阅读器、记事本、IDE 和输入法候选阶段实测；没有有效选区时，原软件的按键行为不能被破坏。桌宠动效监听与翻译快捷键应保持各自独立。

## 白天／夜间主题切换

目前窗口使用深色背景。后续加入白色背景的白天模式和黑色或近黑背景的夜间模式，让用户在设置中切换并保存选择；悬浮窗和设置窗口都要同步切换，文字、按钮、图标和小猫装饰在两种主题下都要清晰可读。

## 拖入图片和 PDF 后翻译

以后可以先把图片或 PDF 下载到本机，再把文件拖到悬浮窗上翻译里面的内容。文字型 PDF 需要提取文本；图片和扫描版 PDF 需要先做 OCR。读不到文件时要给出明确提示，文件内容也不能自动进单词本。目前还没有实现文件拖放和 OCR。

## 单词本还只有一个入口

按钮和独立窗口已经有了，里面还是“准备中”。本机 MySQL、JDBC、表结构和程序里的存取流程要接起来之后，才算真的有词本。

先做翻译成功显示后存一条有效的词或词组，再考虑搜索、次数和历史。失败、重复回调、普通键入和猫拍爪都不能算查词。复习轮播、权重和归档继续放在后面。

## 动效和窗口还有些场景没试完

这次独立界面检查通过过 44 项，包含开关保存、原文隐藏、动画归位和监听启动等。原生输入探针看到了左键区与鼠标活动，输入框也正常收到字；右键区只做了程序映射检查，实际输入还要补。

接下来需要试多显示器、不同缩放、全屏和提权应用，以及切换窗口时会不会影响原软件焦点。动效版本还没有可靠的新截图，不能拿之前的静态截图当动画验证。

设置里的“动态效果”可以关闭，隐藏装饰也会停监听。后面还要观察长时间打字、反复开关和退出程序时的情况；监听如果启动失败，最好也能有明确提示。

具体想做成什么样，继续看 [需求文档](requirements.md)。这里记的是待办，写进来不代表已经修好了。
