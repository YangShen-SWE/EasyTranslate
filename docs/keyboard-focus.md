# 键盘操作与焦点边界

D08 / 源码v2.1.8，2026-10-18。主窗口恢复正常焦点遍历，不再用禁止所有按钮/滚动区聚焦来掩盖抢焦点问题。

## 如何使用

先主动点击悬浮窗口，或在Windows窗口切换器中选择EasyTranslate，再使用下列**窗口内**操作。不是新注册的全局快捷键，不保证窗口切换器在所有Windows/辅助工具配置下的表现。启动应用的首次`Stage.show()`属于主动启动；运行中的译文/状态更新不调用`show`、`toFront`或`requestFocus`，不会因新译文主动打开设置。

| 按键 | 行为 |
|---|---|
| Tab / Shift+Tab | 当前窗口正常前进/后退遍历；禁用的复制按钮、隐藏原文区自然跳过 |
| Space（按钮聚焦时） | 执行该按钮；例如复制、设置、置顶或关闭 |
| Ctrl+C | 仅主窗口中复制当前展示的完整译文；空译文不复制，保留旧结果时仍显示“上次结果”标记 |
| F6 | 聚焦译文滚动区，使用方向键或PageDown/PageUp阅读长文 |
| Shift+F6 | 聚焦可见原文滚动区；原文隐藏时回到译文，不聚焦隐藏控件 |
| Ctrl+, | 主窗口中打开/激活设置；设置内部不覆盖密码框/普通控件自身的快捷键 |
| Esc | 主窗口关闭应用窗口；设置/单词本中仅关闭当前辅助窗口，显式返回主窗口对应入口 |

原文/译文滚动区带焦点内阴影，原有按钮焦点边框保留。设置内的复选框、拒绝按钮、字号滑块、密钥控件与关闭按钮保持默认JavaFX遍历，不屏蔽Tab；设置滚动区可聚焦和翻页。真实剪贴板仅在用户主动复制时写入，不用于选区捕获或翻译回退。

## 为什么自己窗口内的Tab不翻译

生产`WindowsTabObserverService()`默认在合格首次Tab通知前查询前台窗口所属进程：当前应用进程（包含主窗、设置、单词本）或无法识别所属进程时，不发翻译通知。仍调用`CallNextHookEx`，原Tab交给JavaFX/原程序。拒绝也锁定到物理抬起，不能把按住Tab时切到外部窗口变成新的翻译。拒绝的遍历不取消此前已接受的外部请求，也不改D02/D05的UI意图/许可守卫。

这是按键阶段的一次前台进程采样，不是选区快照：外部按下之后再切回应用、窗口切换竞争、UIA提供者和输入法候选等仍有未解决边界；不宣称阻止一切错误来源捕获。候选/敏感场景先关闭在线翻译。已准入的HTTP不能撤回或保证不计费。

`NativeInputProbe`诊断入口显式使用`WindowsTabObserverService(false)`：为了在自身两个输入框内计数，**仅该离线探针关闭自窗口排除**。探针无选区/翻译/配置服务；不能把探针计数等同生产翻译通知。生产应用保留默认`true`，不提供给用户一个关闭此保护的偏好。

## 自动化与人工证据分开

`FloatingKeyboardSmokeTest`为独立JavaFX main，不是JUnit：创建真实FXML/控件皮肤、主窗口、设置窗口和自造文本源窗口，通过本地合成`KeyEvent`检查遍历、按钮Space、局部快捷键、翻页、隐藏原文、辅助窗口Esc及自动更新期间源窗口/焦点/选区保留。复制注入内存假写入器，不读写系统剪贴板；使用临时Preferences并清理，不访问个人设置/凭据，不运行翻译HTTP或UIA，也不启动全局键盘/动效监听。

这比只检查`focusTraversable`属性更强，但仍不是物理键盘、屏幕阅读器、跨进程浏览器/IDE或IME证明。原窗口检查器另做既有布局、同意/拒绝、保留结果、动效/监听生命周期回归；两者不是完整主程序端到端测试。

| 人工案例 | 安全步骤 | 当前状态 |
|---|---|---|
| 跨进程不抢焦点 | 自造外部编辑器文本，保持在线关闭；在受控假响应环境更新译文/状态，核对前台进程/光标/选区不动 | 待验证；同进程自造源窗口自动化不能代替 |
| 应用内Tab不翻译 | 离线计数/假选区服务，主窗、设置、单词本分别Tab与Shift+Tab；通知、选区读取、HTTP应不增加，控件照常遍历 | 待原生验证；纯筛选/组合链测试不调用User32 |
| 物理键盘操作 | 主窗复制、进入设置、长文翻页、关闭；设置拒绝、字号、密钥控件可达，不用真实密钥/文本 | 待验证；自动化仅本地JavaFX事件 |
| 辅助技术/输入布局 | 键盘布局、屏幕阅读器、中文候选、AltGr、缩放和多屏分别记录环境与结果 | 待验证，不宣称通用无障碍/候选兼容 |
| 真剪贴板 | 用户主动用自造译文复制并粘贴到临时编辑器，确认完整文字与失败提示 | 待验证；自动化使用假剪贴板边界 |
