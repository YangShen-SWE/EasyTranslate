# v2.1.8 — D08：可主动键盘操作、自动更新不抢焦点

## 实际改动与用户影响

- 恢复FXML中置顶、关闭、复制、单词本、设置及原文/译文滚动区的正常focusTraversable。禁用复制与隐藏原文仍由JavaFX自然跳过，没有全局禁止遍历。
- 主窗口增加局部Ctrl+C复制、Ctrl+,设置、F6译文/Shift+F6原文、Esc关闭；长文可聚焦后使用方向/翻页键。按钮保留Space与Tab/Shift+Tab，滚动区增加焦点内阴影和辅助名称。
- 设置/单词本Esc只关闭当前辅助窗口；显式关闭后回到主窗口对应入口。译文/状态/错误更新沿用内容绑定和有界resize，**不新增自动show/toFront/requestFocus**，不会自动打开设置。主动启动的首次Stage.show不等同异步译文抢焦点。
- 默认WindowsTabObserverService在合格首次Tab通知前，原生查询前台窗口所属进程：同进程或所属进程未知则拒绝翻译通知。覆盖主窗/设置/词本，不依赖延迟更新的JavaFX焦点标记。拒绝仍锁定到抬起，依旧CallNextHookEx，不吞键、不影响动效缓冲，不使已接受外部请求失效。
- NativeInputProbe为在自己的输入框计数，显式使用WindowsTabObserverService(false)诊断例外；生产应用默认true，未新增关闭此保护的用户设置。此探针本次只编译未启动。
- 提取复制写入器的包级测试注入点；生产仍只在用户主动复制时写系统剪贴板，**不是剪贴板捕获/模拟复制翻译回退**。测试只写内存，不读取或覆盖真实剪贴板。

完整按键用法、自动化边界和人工待验见[键盘与焦点说明](../keyboard-focus.md)。

## 明确未验证与剩余问题

- 同进程自造源窗口+本地合成KeyEvent不代表跨进程编辑器/浏览器、物理键盘、原生User32前台判定、系统快捷键、辅助工具或屏幕阅读器通过。待验矩阵仍标未验，不宣称完整无障碍或候选冲突解决。
- 原生前台进程读取只是一次非原子采样；外部按下后切回应用、A→B→A、窗口内换焦点、后台UIA捕获竞争仍未全面解决。输入法候选中的裸Tab仍无通用检测，候选/敏感场景先关闭在线翻译。
- 没有真实API/网络/计费、私人选区/个人凭据、真剪贴板、实际主进程退出、多屏/缩放或干净安装验证。UI原生动效/监听回归只证明检查器运行过的范围，不等于主程序端到端验收。焦点边框视觉/屏幕阅读器效果没有人工验收。
- 已准入HTTP仍可能发送/完成/计费，不能撤回文本。没有增加自动重试、OCR、数据库、快捷键配置或新全局触发。D09再处理设置保存/恢复健壮性。
